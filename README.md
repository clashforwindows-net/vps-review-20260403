## 评测为什么需要标准

同样一台 VPS，"测出 1Gbps"和"实际 100Mbps"可以同时成立，因为：

- 测速节点不同（国内 vs 海外）
- 测试时间不同（凌晨 vs 晚高峰）
- 样本不同（单次 vs 多次平均）
- 指标不同（别人看带宽，你卡在磁盘 IO）

没有标准 = 无法对比。本文把评测拆成**统一指标 + 统一方法 + 统一算法**，让任何人的结果都能互相印证。

---

## 评测指标体系（6 大维度）

| 维度 | 指标 | 工具 | 单位 | 权重建议 |
|------|------|------|------|---------|
| CPU | 单核/多核得分 | UnixBench / sysbench | 分 | 20% |
| 内存 | 读写带宽 | sysbench / mbw | MB/s | 10% |
| 磁盘 | 顺序/随机 IO | fio / dd | MB/s, IOPS | 20% |
| 网络 | 带宽/延迟/抖动 | iperf3 / ping | Mbps, ms | 25% |
| 稳定性 | 在线率/波动 | 长期监控 | % | 15% |
| 性价比 | 单位成本 | 自算 | 元/单位 | 10% |

> 权重可按用途调整：游戏服务端拉高 CPU/网络；云盘拉高磁盘；代理拉高网络。

## 测试方法论（怎么做才公平）

1. **纯净环境**：刚开机的机器先 `apt update`，关掉占用资源的进程再测
2. **多次取样**：每项至少测 3 次，取中位数，剔除异常值
3. **分时段**：至少包含一次**晚高峰（20-23 点）**，这是最真实的
4. **固定节点**：网络测速用同一组节点（如国内三大运营商入口）
5. **同配置对比**：只对比相近价位的机器，跨价位无意义
6. **记录版本**：内核、系统版本写进报告，便于复现

> 一份合格评测 = 指标 + 方法 + 原始数据 + 环境信息，缺一不可。

## 一键测试脚本（Linux）

保存为 `vps-bench.sh`，`chmod +x` 后运行：

```bash
#!/usr/bin/env bash
# vps-bench.sh —— 基础性能采集（需 root 或 sudo）
set -e
echo "===== VPS 性能评测 $(date) ====="
echo "--- 系统 ---"
uname -a
echo "--- CPU ---"
nproc
lscpu | grep "Model name"
echo "--- 内存 ---"
free -h
echo "--- 磁盘顺序写 (1G) ---"
dd if=/dev/zero of=/tmp/benchtest bs=1M count=1024 conv=fdatasync 2>&1 | tail -1
rm -f /tmp/benchtest
echo "--- 网络 (speedtest-cli) ---"
which speedtest-cli >/dev/null 2>&1 && speedtest-cli --simple || echo "未安装 speedtest-cli"
echo "--- 延迟 (国内示例) ---"
ping -c 5 -W 2 223.5.5.5 2>&1 | tail -3
echo "===== 完成 ====="
```

进阶（需安装）：`sysbench cpu run`、`fio --randread`、`iperf3 -c 节点`。

## 一键测试脚本（Windows PowerShell）

在 Windows 本地测到你 VPS 的延迟/丢包，适合"实际体验"评测：

```powershell
# vps-latency.ps1 —— 测到 VPS 的延迟与丢包
param([string]$Ip="你的服务器IP")
Write-Host "===== 延迟评测 $(Get-Date) =====" -ForegroundColor Cyan
1..20 | ForEach-Object {
    $r = Test-Connection -ComputerName $Ip -Count 1 -ErrorAction SilentlyContinue
    if ($r) { Write-Host "第$_次: $($r.ResponseTime) ms" } else { Write-Host "第$_次: 超时(丢包)" -ForegroundColor Red }
}
Write-Host "===== 完成 =====" -ForegroundColor Cyan
```

> 用法：晚高峰跑一遍，记录平均延迟和丢包率，比看商家宣传真实。

## 评分算法（综合得分怎么算）

对单台 VPS，先让各指标归一化到 0-100，再加权：

```
综合得分 = CPU×0.20 + 内存×0.10 + 磁盘×0.20 + 网络×0.25 + 稳定×0.15 + 性价比×0.10
```

归一化示例（以"该价位上限"为 100）：
- 带宽 480Mbps / 上限 1000Mbps = 48 分（该项）
- 延迟 42ms：<50ms=100，50-100=线性降，>150=20
- 性价比：月费越低分越高（同配对比）

示例（VPSVIP 标准型 港）：
- CPU 80 / 内存 75 / 磁盘 85 / 网络 70 / 稳定 95 / 性价比 80
- 得分 = 80×0.2 + 75×0.1 + 85×0.2 + 70×0.25 + 95×0.15 + 80×0.1
- = 16 + 7.5 + 17 + 17.5 + 14.25 + 8 = **80.25**

> 把候选都算一遍，谁高选谁，比看单一数字科学。

## 常见误区

1. **只看带宽**：延迟和磁盘 IO 往往更影响体感
2. **单次测速**：晚高峰才是真相，至少测 3 次
3. **跨价位比**：50 元机器和 10 元机器比分数没意义
4. **忽略稳定性**：峰值再高，天天掉线也白搭
5. **不记环境**：内核/系统不同，结果不可复现

## 进阶测试命令（可复制）

```bash
# CPU 多核 (sysbench)
sysbench cpu --threads=$(nproc) --time=10 run

# 内存带宽
sysbench memory --memory-oper=read --memory-block-size=1M --memory-total-size=4G run

# 磁盘 4K 随机读 (fio)
fio --name=randread --ioengine=libaio --rw=randread --bs=4k \
  --numjobs=1 --size=1G --runtime=60 --time_based --group_reporting

# 网络吞吐 (iperf3，需对端)
iperf3 -c 对端IP -t 30 -P 4

# 晚高峰延迟采样 (国内 DNS)
ping -c 30 223.5.5.5 | tail -1
```

> 每项跑 3 次取中位数；网络务必含一次晚高峰样本。

## 硬件检测补充

```bash
# 磁盘型号与类型
lsblk -d -o NAME,SIZE,ROTA   # ROTA=0 即 SSD/NVMe
# 内存频率与通道
dmidecode -t memory 2>/dev/null | grep -E "Speed|Locator"
# 是否虚拟化 (KVM 优于 OpenVZ)
systemd-detect-virt
```

> KVM 等全虚拟化可自定内核、开 BBR；OpenVZ 受限，重需求慎选。

## 网络质量评测补充

除带宽外，重点看**拥塞窗口**：晚高峰连续 ping 30 次，若延迟从 40ms 飙到 200ms 又回落，说明线路在拥塞，体验会卡顿。这类“均值好看、抖动大”的机器，综合分应下调。

## 长期追踪建议

单日评测只代表当下。建议：
- 每周固定时段跑一次，记进表格
- 连续 4 周看稳定性趋势（掉线/降速）
- 大促/节假日前后重点测（流量激增场景）
- 形成自己的“机型口碑库”，下次选购直接查
